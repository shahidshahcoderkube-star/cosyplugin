Cosy Appointments Plugin - Comprehensive Architecture & Features Plan
===================================================================

1. Purpose
----------
- To document the complete architecture, feature set, and development approach for the Cosy Appointments plugin.
- To act as the single source of truth for current capabilities, security standards, and future roadmaps.

2. Plugin Architecture (Current)
--------------------------------
- Entry File: `cosy-appointments.php` (Bootstrap, registers PSR-4 Autoloader, handles hooks activation/deactivation).
- Core Directory: `src/`
  * `Admin/`: WordPress backend (Settings, Dashboard, Media Approvals, Orders, Deactivation OTP).
  * `Assets/`: Asset enqueuing and frontend JS/CSS (includes `cosy-alert.js` for centralized popups).
  * `Common/`: Core helper classes (Database migrations, Activator setup, Cron jobs, Logger).
  * `Forms/`: Form data validators and login controller handlers.
  * `Frontend/`: Frontend logic (Shortcodes, AJAX handlers, Form processing, Provider Dashboard).
  * `PostTypes/`: Registration of Custom Post Types (Appointments, Services, Providers) and Taxonomies.
  * `Rest/`: REST API endpoints for external or headless interactions.
  * `Helpers.php`: Global utilities (e.g., `cosy_render_popup` for standardized HTML modals).
- Templates: `templates/` (Contains all frontend PHP views loaded by shortcodes).

3. Comprehensive Feature Set
----------------------------
A. User Roles & Management
   - Customer Role: Can book appointments, manage their own profile, and view order history.
   - Provider Role: Can offer services, manage availability, and access the Provider Dashboard.
   - Admin Role: Full control over settings, provider verifications, and platform earnings.

B. Provider Dashboard (Frontend)
   - Profile Management: Update bio, profile image, and introduction video.
   - Services Management: Add, edit, or remove offered services with specific pricing and durations.
   - Availability Setup: Define weekly working hours (start/end times, break times, slot duration).
   - Non-Working Days (Holidays): Add specific dates where the provider is unavailable.
   - Order Management: View customer bookings, update statuses (Pending, Completed, Cancelled).
   - Invoices: Generate and download PDF receipts for completed orders.
   - Review Management: View customer reviews, approve them to show on the profile, or reject them.
   - Verification Workflow: Upload identity documents (ID/Passport) for admin approval.

C. Customer Booking Flow
   - Browse Providers: Grid view of verified providers with ratings, pricing, and intro videos.
   - Calendar & Scheduling: 
      - Select a service.
      - Pick a date (unavailable dates/holidays are disabled).
      - Select single or multiple contiguous time slots (calculates total duration automatically).
      - Option to book for multiple consecutive weeks.
   - Checkout & Payments: Integrated with Stripe Checkout for secure, off-site payment processing.
   - Order Tracking: Customer dashboard to track booking status.

D. Admin Backend
   - Platform Dashboard: View total earnings, active providers, and recent bookings.
   - Media & Verification Approvals: Review provider identity documents (Approve/Reject with SweetAlert).
   - Global Settings: Configure Stripe API keys, currency, and general plugin options.
   - Deactivation Security: Requires an OTP sent to the admin email before the plugin can be deactivated.

4. UI/UX & Code Standardization
-------------------------------
- SweetAlert2 Centralization: All JavaScript alerts/popups use `CosyAlert` (`src/Assets/js/cosy-alert.js`) to ensure DRY principles and consistent branding (#a44390).
- PHP Modal Components: Dashboard HTML popups are generated using `cosy_render_popup()` (`src/Helpers.php`) to avoid repetitive HTML boilerplate and improve SEO/DOM cleanliness.

5. Security Guidelines
----------------------
- Sanitize all input data (`sanitize_text_field`, etc.).
- Escape output in templates (`esc_html`, `esc_attr`).
- Use nonces for all AJAX actions (`wp_verify_nonce`).
- Capability checks (e.g., `current_user_can('manage_cosy_appointments')`) instead of just checking role strings.
- Secure OTP flow for critical admin actions (Deactivation).
